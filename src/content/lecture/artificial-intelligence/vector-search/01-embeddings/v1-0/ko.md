> **선수** — [수학 » 선형대수 01 벡터](/ko/lecture/math/linear-algebra/01-vectors/).
> 벡터가 무엇이고 차원이 무엇인지는 그쪽에서 가르친다. 여기서는 쓰기만 한다.

**임베딩**은 무언가를 벡터로 바꾸는 일이다. 문장이든 이미지든 상품이든, 하나의
고정 길이 벡터로 만든다.

```python
embed("강아지가 공원에서 뛴다")
# array([ 0.021, -0.184,  0.093, ...,  0.047])   길이 384
```

썸네일이 그리는 게 이것이다. 왼쪽의 서로 다른 것들이 오른쪽 **하나의 공간** 안
점으로 떨어진다.

## 왜 이걸 배우나

검색을 만들려고 한다. 사용자가 "강아지" 를 치면 "개를 산책시키는 법" 문서를 찾아 줘야
한다. 글자는 하나도 겹치지 않는다.

1. 글자가 겹쳐야만 찾는다 → 뜻을 다룰 방법이 필요하다 → **뜻을 좌표로**
2. 좌표로 만들어도 길이가 제각각이면 비교할 수 없다 → **고정 길이**
3. 각자 다른 자로 잰 좌표는 비교가 무의미하다 → **같은 모델, 같은 공간**

## 왜 하필 벡터인가

컴퓨터가 "비슷하다" 를 계산하려면 **비교 가능한 형태**여야 한다. 문자열은 그렇지 않다 —
두 문장 사이에 뺄셈이 없다.

벡터는 다르다. 벡터에는 이미 도구가 갖춰져 있다. 더할 수 있고, 뺄 수 있고, 길이를
잴 수 있고, 사잇각을 잴 수 있다. [선형대수 01–05](/ko/lecture/math/linear-algebra/)
가 만든 도구가 전부 그대로 쓰인다.

그래서 임베딩이 하는 일은 이렇게 요약된다.

> **비교할 수 없는 것을, 비교할 수 있는 것으로 옮긴다.**

옮겨 놓기만 하면 그다음은 수학이 알아서 한다.

## 좌표가 뜻을 담는다는 게 무슨 말인가

핵심은 벡터 자체가 아니라 **벡터들의 배치**다.

임베딩 모델은 대략 이런 규칙으로 훈련된다 — *같이 등장하는 것들은 가까이 놓고, 그렇지
않은 것들은 멀리 놓아라.* 웹 스케일의 텍스트로 이 배치를 오래 반복하면, "강아지" 와
"개" 는 서로 가까운 자리에 앉게 된다. 둘이 나타나는 문맥이 거의 같기 때문이다.

여기서 중요한 것은 **개별 좌표에는 뜻이 없다**는 점이다.

```python
v = embed("강아지")
v[17]   # -0.0413   ← 이 숫자 하나가 뜻하는 것: 없다
```

17번째 값이 "털의 유무" 같은 것을 뜻하지 않는다. 뜻은 **한 벡터가 다른 벡터들에 대해
어디 있느냐**에서만 나온다. 좌표 하나를 꺼내 해석하려는 시도는 대체로 실패한다.

이 성질에는 실무적인 결과가 딸려 온다.

> **모델이 다르면 벡터를 섞을 수 없다.** 서로 다른 공간의 좌표이기 때문이다.

모델 A 로 만든 문서 벡터와 모델 B 로 만든 질의 벡터를 비교하면, 에러 없이 숫자가
나오지만 그 숫자에 의미가 없다. 임베딩 모델을 교체하면 **저장된 벡터를 전부 다시
만들어야 한다.** 검색 품질이 조용히 무너지는 흔한 원인이다.

## 차원은 왜 384인가

$\mathbb{R}^{384}$ 는 그릴 수 없다. 그래도 계산은 $\mathbb{R}^2$ 와 똑같이 된다 —
[선형대수 01](/ko/lecture/math/linear-algebra/01-vectors/) 에서 본 대로 그림은
이해를 돕는 도구지 정의가 아니다.

차원 수는 모델이 정한다. 384, 768, 1536 이 흔하다. 고를 일이 생기면 판단 기준은 둘이다.

| | 낮은 차원 | 높은 차원 |
|---|---|---|
| 표현력 | 미세한 구분을 놓친다 | 더 잘 나눈다 |
| 비용 | 저장·계산이 싸다 | 벡터 하나가 6KB(1536×4byte) |

100만 문서면 1536차원에서 6GB 다. 검색 속도는 대체로 차원에 비례한다. 그래서
"높을수록 좋다" 가 아니라 **과제에 필요한 만큼**이 답이다.

## 손으로 확인해 보기

임베딩이 배치를 만든다는 말을 코드로 확인해 보자.

```python
import numpy as np

docs = [
    "강아지를 산책시키는 방법",
    "반려견 훈련 기초",
    "파이썬 리스트 컴프리헨션",
]
vecs = np.array([embed(d) for d in docs])   # (3, 384)

vecs.shape          # (3, 384)  문서 3개가 같은 공간의 점 3개
np.linalg.norm(vecs[0] - vecs[1])   # 작다 — 둘 다 개 이야기
np.linalg.norm(vecs[0] - vecs[2])   # 크다 — 하나는 코드 이야기
```

`np.linalg.norm(a - b)` 는 [선형대수 02 의 노름](/ko/lecture/math/linear-algebra/02-norm/)
과 [03 의 뺄셈](/ko/lecture/math/linear-algebra/03-vector-operations/) 을 그대로
쓴 것이다. 새 개념이 하나도 없다.

다만 이 방식에는 문제가 하나 있다. **긴 문서가 무조건 불리해진다.** 그 문제와 해법이
다음 차시의 내용이다.

## 한 장 요약

| 물으면 | 답한다 |
|---|---|
| 임베딩이란 | 비교할 수 없는 것을 벡터로 옮기는 일 |
| 왜 벡터인가 | 덧셈·노름·내적이 이미 갖춰져 있어서 |
| 뜻은 어디 있나 | 좌표 하나가 아니라 **다른 벡터들에 대한 배치**에 |
| `v[17]` 의 의미 | 없다. 개별 차원은 해석 대상이 아니다 |
| 모델을 바꾸면 | 저장된 벡터를 **전부 다시 만들어야 한다** |
| 차원 수 | 모델이 정한다. 높을수록 좋은 게 아니라 필요한 만큼 |
