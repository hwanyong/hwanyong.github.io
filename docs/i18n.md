# 다국어 운영 규약

이 사이트는 영어를 정문으로 두고 한국어를 `/ko/` 아래에 둔다.
자동 감지는 없다 — 방문자가 헤더의 언어 칩으로 직접 고른다.

```
en (접두사 없음)              ko (/ko/)
/                        ↔   /ko/
/about/                  ↔   /ko/about/
/log/                    ↔   /ko/log/            ← 목록 1쪽
/log/2/                  ↔   /ko/log/2/          ← 2쪽부터 세그먼트가 붙는다
/lecture/                ↔   /ko/lecture/
/lecture/2/              ↔   /ko/lecture/2/
/project/                ↔   /ko/project/
/privacy/                ↔   /ko/privacy/
/log/first-post/         ↔   /ko/log/first-post/
/project/<계열>/          ↔   /ko/project/<계열>/
/rss.xml                 ↔   /ko/rss.xml
404.html                     언어축 밖. 두 언어를 함께 적는다.
```

**언어 칩은 목록이 아니라 회전이다.** 헤더에는 링크가 하나뿐이고 그것이 ★다음★ 언어를
가리킨다(영어 화면에서 `KO`). 누르면 그 언어로 가고, 로케일이 셋이 되어도
`en → ko → ja → en` 으로 돌 뿐 헤더 폭은 늘지 않는다. 무늬·조명 칩과 같은 방식이다.
화면의 링크가 하나여도 `<head>` 의 hreflang 은 전 로케일을 그대로 낸다 —
검색엔진이 보는 짝은 줄지 않는다.

## 다섯 문장

> ### ① `groupKey`(= log 의 디렉터리 이름 · 개정축의 `series`)는 공개되는 순간 네 가지를 동시에 고정한다
> URL · giscus 검색어 · RSS guid · sitemap `<loc>`.
> 공개 후에는 절대 바꾸지 않는다. 바꿔야 한다면 그것은 새 글을 쓰는 것과 같다.

> ### ② 모든 항목은 모든 로케일의 판본을 갖는다 (완전쌍 불변식)
> `pnpm i18n:verify` 가 강제한다. 번역이 아직 없으면 `pnpm i18n:fill` 이 원문의 사본을
> 만들고 프론트매터에 `untranslated: <원문 로케일>` 을 넣는다.
> 화면은 그 값을 읽어 안내 문구 · `<article lang>` · 목록 배지를 낸다.
> **번역을 마치면 그 줄을 지운다. 그것이 완료 신호다.**
>
> 이 불변식이 있어서 목록 코드는 "그 언어의 본문이 있는 것만" 이라는 단순한 형태를
> 유지하면서도 빈 목록이 하나도 없다. hreflang 쌍도 전 URL 에서 성립한다.

> ### ③ OG 기본 이미지에 글자를 넣는 순간 언어별 이미지가 필요해진다
> 넣으려거든 `LOCALES[locale]` 에 `ogImage` 필드를 추가해 모든 로케일을 채우게 한 뒤에 넣는다.
> (현재 `public/og-default.png` 는 글자 없는 그림이라 언어 중립이다.)

> ### ④ 사람이 통독·수정하지 않은 번역을 커밋하지 않는다
> 문체 취향이 아니라 정책이다 — 검수 없는 대량 번역 게시는 검색엔진의 스팸 정책
> (scaled content abuse)이 드는 명시적 예시이고, 광고 심사에서 사이트 전체를 끌어내린다.
>
> **번역할 시간이 없으면 `untranslated` 사본을 그대로 두는 것이 정답이다.**
> 그 상태는 화면이 정직하게 밝히고 있고, 기계 번역보다 언제나 낫다.
>
> (덧: 번역판은 중복 콘텐츠가 아니다. 검색엔진은 번역을 중복으로 취급하지 않으며
> hreflang 이 그것을 알리는 정식 수단이다. 위험은 중복이 아니라 자동 생성이다.)

> ### ⑤ 계기판 어휘는 번역하지 않는다
> `Log` `Lecture` `Project` `About` `Privacy` · `N ENTRIES`/`N SERIES` · `REV n/m` ·
> `PAGE n / m` · `PREV`/`NEXT` · `v1.0` · `REFLECT`/`EMIT` ·
> `VERTICAL`/`HORIZONTAL`/`GRID`/`NONE` · 언어 코드(`EN` `KO`) · 키캡(`J` `K` `↵` `T`) ·
> **날짜 표기 `YYYY.MM.DD`**.
>
> 날짜에 `Intl.DateTimeFormat(locale)` 을 쓰지 않는다 — 날짜는 모노스페이스로 찍히는
> 계기판 메타데이터라 목록에서 세로로 줄이 맞아야 하고, 기계용 표기는 `<time datetime>`
> 이 ISO 로 따로 낸다.

## 새 글을 쓸 때

```
log     : src/content/log/<groupKey>/<locale>.md
개정축  : src/content/<lecture|project>/<series>/<versionSlug>/<locale>.md
```

- `groupKey` · `series` · `versionSlug` 는 소문자·숫자·하이픈만. 빌드가 검증한다.
- **`groupKey` 와 `series` 는 숫자만으로 이루어질 수 없다**(`2` · `2026` 불가).
  목록의 쪽 번호가 같은 자리에 오기 때문이다 — `/log/2/` 는 2쪽이다.
  규칙은 `src/lib/routes.ts` 의 `URL_KEY` 하나이고 디렉터리 이름과 `series`
  프론트매터가 그것을 함께 읽는다.
- 프론트매터에 **`lang` 을 쓰지 않는다** — 파일 이름이 로케일의 유일한 출처다.
- 프론트매터에 **`key` 를 쓰지 않는다** — 디렉터리 이름이 `groupKey` 다.
- 프론트매터의 `version` 은 표시용("1.0")이고 URL 은 디렉터리 이름(`v1-0`)이 정한다.
- **그 언어의 최신 개정본이 그 언어의 계열 루트 URL 을 갖는다.** 구버전만 세그먼트가 붙는다.

한 언어만 쓰고 `pnpm i18n:fill` 을 돌리면 나머지 언어가 사본으로 채워진다.

## 이미 있는 글에 번역을 얹을 때

1. **`groupKey` 를 확인한다. 새로 짓지 않는다.**
   새로 지으면 URL · giscus · RSS guid 가 전부 갈라진다. 그것은 번역이 아니라 새 글이다.
2. 그 파일의 `untranslated` 줄을 지우고 본문을 번역한다.
   `title` 과 `description` 도 번역한다 — 목록 · `<title>` · `og:description` 이 그 값을 쓴다.
3. **`date` 는 원문의 발행일을 그대로 둔다.** 번역일이 아니다.
   두 판본이 같은 시간축 위치를 가져야 목록 순서가 언어 간에 일치하고,
   개정축에서는 `date` 가 개정 순서를 정하므로 번역일을 쓰면 번역이 최신 개정본이 된다.
4. **giscus 검색어는 손대지 않는다.** 언어 무관 통합이라 같은 Discussion 을 쓰고,
   검색어는 `groupKey` 에서 나오며 `groupKey` 는 1번에서 바뀌지 않았다.
5. `pnpm run ci` — hreflang 쌍이 자동으로 생긴다.
   **손으로 추가할 hreflang 도, sitemap 항목도, 리다이렉트도 없다.**

## 원문이 바뀌었을 때

번역이 아직 없는 사본은 원문과 본문이 같아야 한다. 원문을 고쳤다면:

```bash
pnpm i18n:fill --force    # 사본을 원문에 다시 맞춘다
```

`pnpm i18n:verify` 가 어긋난 사본을 잡아 준다. 그 메시지는 두 갈래를 안내한다 —
번역을 시작한 것이면 `untranslated` 줄을 지우고, 원문이 바뀐 것이면 `--force` 를 돌린다.

## 목록과 쪽

| 화면 | 쪽 나눔 | 총 개수 표시 |
|---|---|---|
| `/log/` | **있음** (10개/쪽) | 목록 끝 `.pager` |
| `/lecture/` | **있음** (10개/쪽) | 목록 끝 `.pager` |
| `/project/` | 없음 | 없음 |
| `/` (홈) | 없음 | 없음 |

- **총 개수는 헤더가 아니라 목록 끝에 있다.** 헤더 우측 칩(`.site-status`)은 화면마다
  뜻이 달라지는 자리이고(`REV 2 / 2` · `404` · 방침 시행일), "글이 몇 개인가" 는
  목록을 다 읽은 사람이 묻는 물음이라 답도 그 자리에 있어야 한다.
- **홈은 쪽을 나누지 않는다.** 세 축을 한 시간축에 섞어 "언제 무엇을 했는지" 를 한눈에
  보이려는 화면이라, 그 그림을 쪽으로 자르면 화면의 목적이 사라진다.
  개수가 부담이 되면 쪽이 아니라 "최근 N개" 로 자르는 편이 맞다.
- **`project` 도 나누지 않는다.** 계열 수가 글처럼 늘지 않고 썸네일이 붙은 목록이라
  한 화면에 전부 보이는 편이 고르기 쉽다. 붙일 때는 라우트를 `[...page].astro` 로
  바꾸고 `paginate` 를 태우는 것이 전부다.
- **쪽 주소는 `routes.ts` 의 `pageHref` 하나에서 나온다.** `paginate()` 가 주는
  `page.url.next` 를 쓰지 않는다 — 그 값에는 끝 슬래시가 없어(`/log/2`) 내부 링크마다
  리다이렉트가 낀다. 더 중요한 것은 화면의 `PREV`/`NEXT` 와 `<head>` 의 hreflang 이
  같은 함수에서 나와야 서로 다른 쪽을 가리킬 수 없다는 점이다.
- **n쪽의 hreflang 짝은 다른 언어의 같은 n쪽이다.** 완전쌍 불변식 덕분에 두 언어의
  항목 수가 같으므로 n쪽은 전 로케일에 존재한다.

## 항목이 0개인 축

**감추지 않는다.** `/lecture/` 는 강의가 하나도 없어도 네비에 있고 URL 도 있다.
비었다는 사실은 목록이 `UI[locale].emptyLecture` 로 직접 말한다.

예전에는 빈 축을 네비와 sitemap 에서 통째로 뺐다. 그러면 축이 "아직 없는 것" 이 아니라
"존재하지 않는 것" 이 되어, 첫 항목을 넣기 전까지 그 자리를 확인할 방법이 없었다.

대신 지켜야 할 것이 하나 있다 — **항목이 0개인 화면에는 광고를 싣지 않는다.**
publisher content 가 없는 화면의 광고는 Google Publisher Policies 위반이다.
게이트는 목록 페이지의 `ads={page.data.length > 0}` 이다.

## 로케일을 하나 더 켤 때

`src/lib/i18n.ts` 의 `LOCALE_CODES` 에 코드를 추가하면 다음이 **전부 컴파일 에러**가 된다.
번역 없이 로케일을 켜는 것이 타입 수준에서 불가능하다는 뜻이다.

| 파일 | 무엇이 막히는가 |
|---|---|
| `src/lib/i18n.ts` | `LOCALES` 에 그 로케일의 메타(htmlLang/ogLocale/hreflang/giscusLang/label/endonym) |
| `src/lib/ui.ts` | `UI` 와 각 `languageNames` |
| `src/lib/privacy.ts` | `POLICY_TEXT` 전문 |
| `src/lib/profile.ts` | `INTRO` · `CAREER` · `ACCOUNTS` 의 `LocalizedText` 전부 |

콘텐츠는 `pnpm i18n:fill` 이 사본으로 채운다. 폰트는 `docs/fonts.md` 를 볼 것.

## 배포 후

- **Search Console 재등록·sitemap 재제출은 필요 없다.** 소유권 파일과 sitemap 주소가 그대로다.
  ★ `public/google1af69c42d9e600f9.html` 을 지우지 말 것 — 지우면 소유권이 풀린다.
- 새로 볼 보고서 둘: **설정 → 국제 타겟팅**(hreflang 오류), **페이지 → 대체 페이지**.
  이 둘이 `tools/verify-site.ts` 의 외부 검증이다 — 우리 검사는 head ↔ sitemap 일치만 보고,
  "검색엔진이 그 쌍을 실제로 받아들였는가" 는 거기서만 보인다.
- **`/ko/` 를 별도 속성으로 등록하지 않는다.** 나누면 hreflang 쌍이 속성 경계를 넘어
  보고서가 반쪽이 된다.
- 방문 통계에서 언어는 **Path 로 읽는다** — `Path contains /ko/` 가 한국어 트래픽이고
  영어는 뺄셈이다. Cloudflare Web Analytics 에는 브라우저 언어 dimension 이 없다.

## CI 가 지키는 것

`pnpm run ci` 가 순서대로 돈다.

| 단계 | 무엇을 막는가 |
|---|---|
| `tools/check-collisions.mjs` | 이 맥에서는 재현되지 않는 파일명 충돌 |
| `tools/i18n-verify.ts` | 완전쌍 불변식 · 화면 문구가 UI 사전 밖에 박히는 것 |
| `tools/fonts.mjs build --check` | 생성된 폰트 CSS 가 락파일과 어긋나는 것 |
| `astro check` | 타입. `astro.config.ts` 의 옵션 위치 오류 포함 |
| `astro build` | 라우트 충돌 · 콘텐츠 슬러그 중복(`prerenderConflictBehavior: 'error'`) |
| `tools/verify-site.ts` | head hreflang ↔ sitemap 불일치(**주소 값까지**) · 언어 누수 · 끝 슬래시 없는 내부 링크 · 네비 ↔ NAV_SECTIONS · 같은 본문 두 URL · 404 규약 |
