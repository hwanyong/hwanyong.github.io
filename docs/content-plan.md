### 2-1. ★ 강의는 자기 과목의 내용만 다룬다

볼트의 **적용렌즈**는 수학 원자를 `![[…]]` 로 끌어와 그 아래 AI 살을 붙인 구조다.
그것은 *한 사람이 배운 순서*였지 *가르치는 단위*가 아니다. 강의로 옮기면서 가른다.

```
버린다 — 볼트의 학습 구조를 그대로 옮기는 안
  math/linear-algebra/05-dot-product
    ├ 내적의 정의 · 기하 · 직교               ← 수학
    └ 임베딩 유사도 · RAG 에서 어떻게 쓰나     ← AI 가 수학 강의 안에 들어앉는다

채택 — 과목 분리 + 상호 안내
  math » 선형대수 05 내적            인공지능 » 벡터 검색 02 유사도
    내적의 정의 · 기하 · 직교           유사도 · 인덱싱 · 검색
    (임베딩 이야기 없음)                (코사인 정의 없음)
         │                                    │
         └── 쓰이는 곳 ──────────→ ←── 선수 ──┘
              두 줄이 서로를 가리키되, 내용은 넘어가지 않는다
```

- **선수 고지** — AI 차시 머리에 한 줄. "선수: 수학 » 선형대수 05 내적". 개념을 다시 가르치지 않는다.
- **쓰이는 곳** — 수학 차시 말미에 한 줄. "이 개념이 일하는 곳: 인공지능 » 벡터 검색 02".
- 둘 다 **본문 문단**으로 쓴다. 프론트매터 필드를 새로 파지 않는다 —
  화면에 안 나오는 필드는 두지 않는다는 규약(`content.config.ts`)이고,
  차시가 0개인 지금 필드를 설계하면 근거 없는 추측 설계가 된다. 승격 판단은 §9-5.

**렌즈 28편은 1:1 차시가 되지 못한다.** 고유분을 실측하면 대부분 **2.5~4K, 헤딩 하나**
(`🧠 AI 특화 연결`)뿐이다. 두꺼운 것은 셋뿐이다 — `07 RAG 검색엔진`(6.1K, 코드 있음) ·
`29 CNN 예고`(6.7K) · `04 내적`(4.2K). 그래서 렌즈는 차시가 아니라 **AI 코스의 재료**로
쓰고, 목차는 AI 의 문제(임베딩 → 유사도 → 검색)로 다시 짠다. 수학 순서를 따라가지 않는다.

## 3. 발행하지 않는 것 — 경계선

볼트는 이미 `github.com/hwanyong/notebooks` 로 공개 미러된다. **그 경계선을 그대로 쓰면 안 된다.**
미러는 학습 노트 저장소지만 이 블로그는 광고가 붙는 발행물이라(`src/lib/site.ts` 의 `ADSENSE`)
한 칸 더 보수적으로 잡는다.

| | 볼트 미러 | 이 블로그 |
|---|---|---|
| `(figure)` 내가 다시 그린 그림 | 공개 | **공개** |
| `(replica)` 책 도판 전사 모사본 | 공개 | **보류** — 배치·수치가 지면 그대로다 |
| `(book-scan)` · `(ext-src)` | 비공개 | **비공개** |
| `📘 책 핵심` 콜아웃(책 서술 전사) | 볼트에 존재 | **그대로 옮기지 않는다** |
| 참고-출처정리 7편(남의 글 정리) | 공개 | **미발행** |

수식·정의·정리 자체에는 저작권이 없다. 걷어낼 것은 **표현과 지면**이다 —
같은 정리를 내 문장·내 그림·내 코드로 다시 쓰면 그 차시는 내 글이다.
책은 코스 표지의 "참고서" 목록과 차시의 절 번호로만 가리킨다.

## 4. lecture — 코스와 차시

### 4-1. 과목 — `artificial-intelligence` 신설 (2026-08-21 반영 완료)

기존 여섯(math · computer-science · earth-science · chemistry · physics · biology)에
**인공지능을 일곱 번째로 넣었다.** `src/lib/subjects.ts` 에 반영돼 있다.

```
math · computer-science · artificial-intelligence · earth-science · chemistry · physics · biology
                          └ 신설. code AI · en Artificial Intelligence · ko 인공지능
```

**이름을 `artificial-intelligence` 로 고른 이유** (슬러그는 URL 이라 공개 후 못 바꾼다):

- 나머지 여섯이 전부 **온전한 학문명**이다. 그 사이에 `ai-ml` 같은 약어 조합이 끼면
  혼자 다른 종류의 이름이 된다.
- **`machine-learning` 보다 볼트를 정확히 덮는다.** 볼트 커리큘럼은 4단계에서
  RAG·서빙·프로덕션(AI 엔지니어링)까지 간다 — 그 구간은 기계학습이 아니다.
  `machine-learning` 으로 이름 붙이면 마지막 단계가 과목 밖으로 밀려난다.
- `code: 'AI'` 는 두 글자로 `CS` 와 같다. 기존 MATH·EARTH·CHEM·PHYS·BIO 의
  폭 안에 들어간다 — 계기판 어휘군이라 폭이 튀면 격자가 흐트러진다.
  `AI/ML` 은 슬래시가 들어가 혼자 다른 모양이 된다.
- 배열에서 `computer-science` 바로 뒤에 넣어 형식·계산 과학(MATH·CS·AI)이
  위 블록, 자연과학(EARTH·CHEM·PHYS·BIO)이 아래 블록이 되게 했다.

**바꾼 곳은 `subjects.ts` 하나뿐이다.** `SUBJECT_SLUGS` 가 SSOT 라
`content.ts`(`Object.keys(SUBJECTS)`)·`verify-site.ts`(슬러그로 정규식 조립)·
세 화면이 전부 자동으로 따라온다. 코스가 0개인 과목은 URL 을 만들지 않으므로
(`lecture/[subject]/[...page].astro` 의 `courses.length === 0` 가드) 빈 과목이 하나
늘어도 sitemap 은 그대로다. 곁들여 "과목이 여섯" 이라 박혀 있던 주석 세 곳과
`docs/i18n.md` 한 줄에서 **숫자를 뺐다** — `SUBJECT_SLUGS.length` 의 사본이라
과목을 늘릴 때마다 조용히 거짓이 되던 자리다.

## 7. 선행 조건 — 기술 *(2026-08-21 전부 해결)*

### 7-1. 수식 — "스위치 한 줄" 이 아니었다 ★

**이 절의 초안은 틀렸다.** `features.math: true` 를 켜면 될 줄 알았는데, 그것은
**렌더가 아니라 표시**다. 켜면 수식이 이렇게 나온다.

```html
인라인  <code class="language-math math-inline">\lVert v \rVert</code>
블록    <pre><code class="language-math math-display">…</code></pre>
```

LaTeX 원문이 고정폭으로 찍힐 뿐이다. **필요조건이지 충분조건이 아니다.**
실제로 조판하려면 렌더러를 따로 물려야 한다.

세운 파이프라인은 이렇다(`tools/katex-math.ts`).

```
$…$ / $$…$$  ──▶  Sätteri math (표시)  ──▶  katexMath (mdast)  ──▶  MathML
                                              KaTeX output:'mathml'
```

두 가지가 실측으로 뒤집혔다.

- **hast 가 아니라 mdast 다.** 처음엔 hast 에서 `code.language-math` 를 갈아 끼웠는데
  인라인만 되고 **블록만 조용히 실패**했다. 사용자 hast 플러그인은 highlight 플러그인
  ★뒤★ 에 등록되는데 블록 수식도 hast 에서는 `<pre><code>` 라 Prism 이 먼저 집어 간다.
  `syntaxHighlight.excludeLangs: ['math']` 도 안 먹는다 — highlight 는 className 이
  아니라 `code.data.lang` 을 보는데 수식 블록에는 그 값이 없어 `plaintext` 로 잡힌다.
  mdast 에서 걷어내면 `<pre>` 자체가 생기지 않아 마주칠 일이 없다.
- **출력은 MathML 이다.** KaTeX 기본 출력은 katex.css + 전용 폰트 20여 개(≈300KB)를
  요구한다. 이 저장소는 영어 페이지 총량을 100.2KB 로 깎아 둔 곳이라(`docs/fonts.md`)
  그 파이프라인에 300KB 를 얹을 수 없다. MathML 은 **CSS 0 · 폰트 0 · 런타임 JS 0** 이다.

`throwOnError` 는 켜 둔다 — 끄면 깨진 수식이 빨간 글씨로 **발행된다.**

**`wikilinks` 는 켜지 않기로 했다**(§9-8 마감). 볼트 `[[링크]]` 대상 상당수가 블로그에
없는 노트(MOC·용어집·암기장)라, 켜면 그것들이 조용히 죽은 링크가 된다. 손으로 고친다.

### 7-2. 이미지 — 도구 둘로 갈랐다

역할이 다르므로 소유자를 나눴다.

| | 무엇 | 어디 | 누가 만드나 |
|---|---|---|---|
| **본문 그림** | 볼트의 `(figure)` | `/images/figures/` | `pnpm images:vault` 가 볼트에서 가져온다 |
| **썸네일** | 카드용 도형 | `/images/lecture/thumb/` | `pnpm images:thumb` 이 직접 그린다 |

**볼트 그림을 썸네일로 쓰지 않는 이유.** 볼트의 `(figure)` 는 라벨·눈금·범례가 붙은
matplotlib 도판이라 크게 볼 때 읽으라고 만든 것이다. 갤러리 카드는 480×270 이고
그 안에서 축 라벨은 뭉갠 점이 된다.

**썸네일에 글자를 넣지 않는 이유.** `<img>` 로 들어간 SVG 는 이 사이트의 웹폰트를
불러오지 못한다. 글자를 넣으면 기기마다 다른 시스템 폰트로 떨어져 격자의 인상이 흔들린다.
게다가 제목은 카드 바로 아래에 글자로 이미 있다.

**`tools/vault-images.ts` 의 존재 이유는 복사가 아니라 마커 가드다.** 같은 그림이
`(figure)` 와 `(book-scan)` 두 벌로 있는 경우가 실제로 있고(파일럿 11장 중 4장이 그랬다)
둘은 정규화하면 같은 이름이 된다. 이름만 보고 고르면 책 스캔이 그대로 나간다.
후보가 여럿이면 own work 를 고르고, own work 가 하나도 없으면 **복사하지 않고 죽는다.**

무엇을 옮길지는 **콘텐츠가 정한다** — `/images/figures/<이름>` 참조가 곧 주문서다.
매니페스트를 따로 두지 않는 이유: 두 벌이 되면 어긋나고, 어긋나면 아무도 안 쓰는 그림이
`public/` 에 쌓인다.
